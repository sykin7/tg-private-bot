
# 🤖 Telegram 私聊转发机器人 (Modmail Bot)

这是一个基于 Python 的 Telegram 机器人，用于将用户发送给机器人的私聊消息转发到管理员所在的群组。管理员在群组内回复即可直接将消息传达给用户。

该项目包含自动垃圾广告过滤、新用户验证码验证、防刷屏限制以及完整的黑名单管理功能。

## ✨ 主要功能

  * **私聊转发**：用户发给机器人的消息会自动转发到管理员群组（支持自动创建讨论组 Topic）。
  * **双向回复**：管理员在群组内回复消息，机器人会自动转发回对应的用户。
  * **智能反垃圾**：集成云端规则库和自定义关键词，自动拦截广告和违规内容。
  * **人机验证**：新用户必须完成数学题或验证码验证才能发送消息，防止机器滥用。
  * **防刷屏**：内置速率限制（Rate Limit），防止用户恶意轰炸。
  * **持久化存储**：使用 SQLite 数据库保存用户状态和黑名单（支持 Docker 挂载）。
  * **健康检查**：内置 HTTP 服务，适配 Leaflow/Zeabur 等平台的健康监测。

## ⚙️ 环境变量配置 (Environment Variables)

这是最重要的一步。无论你在哪里部署（Leaflow, Zeabur, VPS），都需要设置以下环境变量：

### 必填项 (必须设置)

| 变量名 | 示例值 | 说明 |
| :--- | :--- | :--- |
| `BOT_TOKEN` | `123456:ABC-DEF...` | 从 BotFather 获取的机器人 Token |
| `OWNER_ID` | `123456789` | 你的 Telegram 数字 ID (用于最高权限) |
| `ADMIN_IDS` | `123456789,987654` | 管理员 ID 列表，用英文逗号分隔。只有这些人能回复消息 |
| `ADMIN_GROUP_ID` | `-1001234567890` | 接收消息的群组 ID (必须以 -100 开头) |
| `PORT` | `8080` | 程序监听端口，通常填 8080 |
| `DB_FILE` | `/data/bot_data.db` | **重要**：为了防止数据丢失，必须填这个路径 |

### 选填项 (可自定义)

| 变量名 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `VERIFICATION_TIMEOUT` | `300` | 验证码超时时间 (秒) |
| `BLOCK_THRESHOLD` | `5` | 验证失败几次后自动封禁 |
| `CUSTOM_SPAM_KEYWORDS` | `(空)` | 自定义屏蔽词，逗号分隔 (如: `卖卡,兼职`) |
| `CAPTCHA_MODE` | `math` | 验证码模式：`math` (数学题) 或 `token` (字母数字) |
| `BACKUP_GROUP_ID` | `(空)` | 备份群组 ID，所有消息会额外抄送一份到这里 |

## 🚀 部署指南

### 推荐：在 Leaflow / Zeabur 上部署 (Docker)

1.  **上传代码**：将包含 `bot.py`, `Dockerfile`, `requirements.txt` 的文件夹上传到你的 Git 仓库或直接连接部署。
2.  **设置变量**：在服务的设置页面，填入上面列出的 **所有必填环境变量**。
3.  **挂载存储 (Persistent Volume)**：
      * **非常重要**：为了防止重启后用户数据丢失，你必须添加一个存储卷。
      * **挂载路径 (Mount Path)**：填写 `/data`
      * 这样数据库文件就会保存在云盘里，而不是临时的容器里。
4.  **启动服务**：部署完成后，机器人即可开始工作。

### 备选：在 VPS 上直接运行 (Python)

1.  安装 Python 3.9+。
2.  安装依赖：
    ```bash
    pip install -r requirements.txt
    ```
3.  设置环境变量并运行（Linux 示例）：
    ```bash
    export BOT_TOKEN="你的Token"
    export OWNER_ID="你的ID"
    export ADMIN_IDS="你的ID"
    export ADMIN_GROUP_ID="-100xxxx"
    export DB_FILE="bot_data.db"

    python bot.py
    ```

## 🎮 使用说明

### 1\. 管理员如何回复？

  * 当用户发消息给机器人时，消息会转发到你配置的 `ADMIN_GROUP_ID` 群组。
  * 机器人会尝试为每个用户创建一个 **Topic (话题)**。
  * **方法**：直接在群组里，**引用 (Reply)** 那条转发过来的消息，输入回复内容即可。
  * 机器人会提示：“已将您的回复转发给用户。”

### 2\. 管理员命令

只有在 `ADMIN_IDS` 里的用户可以使用以下命令：

  * `/block <用户ID>`：将指定用户加入黑名单，对方无法再发送消息。
      * 示例：`/block 123456789`
  * `/unblock <用户ID>`：将指定用户移出黑名单。
      * 示例：`/unblock 123456789`

### 3\. 注意事项

  * **群组设置**：建议将管理员群组升级为 **Supergroup (超级群)** 并开启 **Topics (话题)** 功能，这样每个用户的消息会自动分类到不同的话题中，管理更清晰。
  * **私聊限制**：管理员不要直接私聊机器人发送指令，所有操作请在管理员群组内完成（防止死循环逻辑）。

## 🛠 常见问题排查

**Q: 机器人不回复/不转发？**
A: 检查 `ADMIN_GROUP_ID` 是否正确（必须是 -100 开头的 ID）。确保机器人已经被拉入该群组，并且拥有 **发送消息** 和 **管理话题** 的权限。

**Q: 数据重启后丢失了？**
A: 检查你是否在云平台正确挂载了 `/data` 目录，并确保 `DB_FILE` 环境变量设置为 `/data/bot_data.db`。

**Q: 总是提示“Database is locked”？**
A: 代码已优化并发处理，如果依然出现，说明磁盘 I/O 极慢，但在正常云平台上极少发生。
